# HanGo MVP Definition

Version: 1.0

Status: Official

Last Updated: August 2026

---

# Purpose

This document defines the exact scope of the HanGo Minimum Viable Product.

Its purpose is to prevent unnecessary expansion during development and ensure that the first release validates the core HanGo learning experience.

The MVP must prove that learners can improve their Chinese through:

- Structured real-life scenarios.
- Contextual lessons.
- AI-supported explanations.
- Speaking practice.
- Writing practice.
- Missions.
- Competency-based progress.

Anything not required to validate this learning loop should remain outside the MVP.

---

# MVP Objective

The HanGo MVP must validate three main assumptions:

1. Learners prefer a structured learning path instead of using an isolated AI chatbot.

2. A context-aware AI Teacher improves comprehension and practice.

3. Scenario-based learning helps learners use Chinese more confidently in real situations.

The MVP is not intended to provide the complete HanGo vision.

It is intended to prove that the core model works.

---

# Target Learner

The initial MVP is designed for learners who:

- Already understand basic Chinese.
- Are approximately between HSK 3 and HSK 5.
- Want to improve practical communication.
- Need more speaking and writing practice.
- Want guidance beyond vocabulary memorization.
- Study independently.
- Use English or Spanish as an explanation language.

Complete beginners are not the primary target of the MVP.

Advanced HSK 6–9 learners may use some features, but the initial content will not fully serve their needs.

---

# Core MVP Value Proposition

HanGo provides a structured Chinese learning journey based on real-life communication, supported by a persistent AI Teacher that understands the learner's current lesson and progress.

The MVP must demonstrate this complete value proposition.

It should not become only:

- A chatbot.
- A vocabulary application.
- A pronunciation tool.
- A lesson library.
- An HSK question bank.

These elements must work together as one learning system.

# MVP Scenario Scope

The MVP should contain three complete scenarios.

## Scenario 1 — Restaurant

Primary level:

Intermediate.

Communication outcomes:

- Enter a restaurant.
- Request a table.
- Ask for the menu.
- Order food and drinks.
- Ask about ingredients.
- Express preferences.
- Explain a dietary restriction.
- Request assistance.
- Ask for the bill.
- Resolve a basic service problem.

---

## Scenario 2 — Hotel

Primary level:

Intermediate.

Communication outcomes:

- Make or confirm a reservation.
- Check in.
- Ask about hotel facilities.
- Request services.
- Ask for directions.
- Report a room problem.
- Request a solution.
- Extend a stay.
- Check out.

---

## Scenario 3 — Shopping

Primary level:

Intermediate.

Communication outcomes:

- Ask whether a product is available.
- Ask about price.
- Ask about size, color, or model.
- Compare products.
- Request to try something.
- Negotiate when culturally appropriate.
- Ask about payment.
- Request an exchange or return.
- Explain a problem with a purchase.

---

# Scenario Structure

Each MVP scenario should contain:

- Scenario introduction.
- One difficulty level.
- Four core lessons.
- One final scenario mission.
- Scenario progress.
- Scenario mastery status.

The MVP therefore contains:

```text
3 scenarios

12 core lessons

3 final scenario missions
```

This amount is sufficient to validate the learning architecture without creating an excessive initial content burden.

---

# Lesson Structure

Each core lesson follows the approved learning sequence:

```text
1. Situation

2. Dialogue

3. Comprehension

4. Vocabulary

5. Grammar

6. Guided Practice

7. Speaking

8. Writing

9. Quiz

10. Lesson Mission

11. Reflection
```

Some steps may be brief, but the learning flow must remain complete.

---

# Minimum Lesson Content

Each lesson should include approximately:

- 1 real-life situation.
- 1 main dialogue.
- 8 to 15 vocabulary items.
- 1 to 2 grammar points.
- 4 to 8 guided exercises.
- 1 speaking activity.
- 1 short writing activity.
- 1 quiz containing 5 to 10 questions.
- 1 practical lesson mission.
- 1 reflection summary.

These quantities are guidelines.

Educational quality is more important than reaching exact numerical targets.

## Lesson 1 — Entering and Ordering

Learner outcomes:

- Request a table.
- Ask for the menu.

- Use basic polite requests.

---

Learner outcomes:

- Explain simple dietary restrictions.

---

Learner outcomes:

- Request changes.
- Report a missing item.

---

Learner outcomes:

- Ask for the bill.
- Ask about payment methods.

The learner must complete a restaurant interaction from arrival to payment.

The AI introduces at least one unexpected event.

Possible events:

- A dish is unavailable.
- The order is misunderstood.
- The learner must explain an ingredient restriction.
- The bill contains a mistake.

# AI Teacher MVP Scope

The AI Teacher must be available throughout the authenticated application.

## Required Capabilities

- Answer text questions.
- Understand the current page.
- Understand the current lesson.
- Understand selected dialogue content.
- Explain vocabulary.
- Explain grammar.
- Explain corrections.
- Generate additional examples.
- Generate short practice activities.
- Use English or Spanish explanations.
- Respond in Chinese when requested.
- Preserve the current conversation during the session.

## Required Modes

- Tutor.
- Practice.
- Review.

## Optional MVP Capability

- Basic Conversation mode through text.

## Excluded From the MVP

- Long-term personal memory across all sessions.
- Fully autonomous study planning.
- Advanced emotional modeling.
- Real-time voice interruption.
- Multiple AI tutor personalities.
- AI avatars.

---

# AI Teacher Interface Scope

The MVP includes:

- Collapsed AI Teacher button.
- Desktop side panel.
- Expanded panel.
- Mobile drawer or full-screen interface.
- Conversation history.
- Context indicator.
- Suggested prompts.
- Text input.
- Basic microphone input when speaking services are available.

The AI Teacher must not require the learner to manually copy lesson content.

# Audio Scope

The MVP audio system includes:

- Dialogue audio.
- Sentence-level playback.
- Vocabulary pronunciation.
- Normal-speed playback.
- Slow-speed playback.
- Replay.
- Active dialogue-line highlighting.
- Generated audio caching.

The system may use external TTS providers through a provider abstraction.

The frontend must never expose private provider credentials.

# Speaking MVP Scope

The MVP Speaking Lab includes four modes.

## Pronunciation

The learner listens and repeats a word or sentence.

Feedback may include:

- Transcript.
- General clarity.
- Important syllable issues.
- Basic tone observations.
- Retry recommendation.

---

## Shadowing

The learner listens to a sentence and repeats it.

The system compares:

- Timing.
- Fluency.
- General pronunciation.
- Completeness.

---

## Guided Conversation

The AI conducts a short conversation based on an existing scenario.

The interaction may be turn-based rather than fully real-time.

---

## Role Play

The learner assumes a role inside one of the MVP scenarios.

The AI responds as the other participant.

---

## Speaking Requirements

The MVP must support:

- Microphone permissions.
- Voice recording.
- Speech-to-Text.
- Recording playback.
- Transcript display.
- Basic feedback.
- Retry.
- Attempt history.

---

## Speaking Limitations

The MVP does not require:

- Perfect phonetic evaluation.
- Real-time interruption.
- Accent classification.
- Regional accent selection.
- Advanced waveform analysis.
- Debate practice.
- Presentation analysis.
- Interview simulation outside the approved scenarios.

Pronunciation feedback should be presented as educational guidance, not absolute phonetic truth.

---

# Writing MVP Scope

The MVP Writing Lab includes:

- Sentence writing.
- Short messages.
- Short paragraphs.
- Practical scenario responses.

The learner receives feedback on:

- Grammar.
- Vocabulary.
- Naturalness.
- Communication clarity.
- Important corrections.

The system should display:

- Original response.
- Corrected response.
- Explanation.
- Rewrite action.

The AI should not generate the complete initial response before the learner attempts the task.

---

# Exercise Scope

The MVP includes:

- Multiple choice.
- True or false.
- Fill in the blank.
- Sentence ordering.
- Matching.
- Short written response.

The MVP does not require:

- Complex drag-and-drop activities.
- Multiplayer exercises.
- Advanced adaptive exercise generation.
- Image-based examination systems.

---

# Quiz Scope

Each lesson quiz includes:

- Vocabulary questions.
- Grammar questions.
- Comprehension questions.
- Listening questions where audio exists.
- Basic reading questions.

Quiz functionality includes:

- Attempts.
- Score.
- Feedback.
- Results summary.
- Stored result.
- Review recommendation.

The MVP does not require official HSK simulation exams.

---

# Mission Scope

The MVP includes two mission levels.

## Lesson Mission

A short practical interaction that verifies the lesson objective.

Duration:

Approximately 2 to 5 minutes.

---

## Scenario Mission

A larger interaction combining the complete scenario.

Duration:

Approximately 5 to 10 minutes.

---

## Mission Requirements

Each mission includes:

- Context.
- Learner role.
- AI role.
- Communication objective.
- Success conditions.
- Text interaction.
- Voice interaction when available.
- Dynamic AI responses.
- Completion report.
- Retry option.

---

# Mission Evaluation

Mission evaluation should consider:

- Communication success.
- Task completion.
- Relevant vocabulary.
- Relevant grammar.
- Clarity.
- Fluency when voice is used.
- Ability to respond to unexpected events.

The learner should not fail only because of minor grammar mistakes when communication succeeds.

---

# Progress Scope

The MVP tracks:

- Lesson completion.
- Scenario completion.
- Exercise results.
- Quiz results.
- Mission results.
- Speaking attempts.
- Writing attempts.

- API failures.
- Authentication failures.
- AI request failures.
- Audio generation failures.
- Speech recognition failures.
- Response latency.
- AI usage cost.

# Performance Requirements

The MVP should target:

- Fast initial page loading.
- Responsive navigation.
- Autosave without blocking.
- Clear AI loading states.
- Smooth audio playback.
- Acceptable mobile performance.
- Recovery from temporary service failures.

The learner should be able to continue reading lesson content even if an AI or audio service temporarily fails.

---

# Accessibility Requirements

The MVP must include:

- Keyboard navigation.
- Visible focus states.
- Accessible labels.
- Sufficient contrast.
- Scalable text.
- Audio transcripts.
- Captions where applicable.
- Non-voice alternatives.
- Non-drag alternatives for interactive exercises.

Accessibility must be considered during implementation, not postponed until after release.

---

# Privacy Requirements

The MVP must clearly communicate the handling of:

- Account data.
- Learning progress.
- AI conversations.
- Writing responses.
- Voice recordings.
- Analytics data.

Learners should be able to:

- Access relevant preferences.
- Disable optional recording retention.
- Request deletion of their account.
- Understand when their content is sent to external AI or audio providers.

---

# Security Requirements

The MVP requires:

- Secure authentication.
- Backend authorization.
- Input validation.
- Rate limiting.
- Protected API credentials.
- Private learner recordings.
- Secure file access.
- Safe error handling.

# MVP Acceptance Criteria

The HanGo MVP is complete when:

1. A learner can register and authenticate.

2. A learner can complete onboarding.

3. A learner receives a starting recommendation.

4. A learner can access all three scenarios.

5. A learner can complete twelve structured lessons.

6. A learner can ask the AI Teacher about the current lesson.

7. A learner can listen to dialogue and vocabulary audio.

8. A learner can complete speaking activities.

9. A learner can complete writing activities.

10. A learner can complete exercises and quizzes.

11. A learner can complete lesson and scenario missions.

12. A learner receives educational feedback.

13. Learning progress is saved and recoverable.

14. Competency progress is updated.

15. The Dashboard provides a clear next action.

16. Core functionality works on desktop and mobile web.

17. Technical errors do not destroy learning progress.

18. Basic accessibility requirements are satisfied.

19. Security and privacy requirements are implemented.

20. The complete learning loop has been tested by real learners.

---

# Scope Change Rule

Any proposed MVP feature must answer:

1. Is it required to validate the core learning model?

2. Does the learning loop fail without it?

3. Can the objective be achieved using an existing MVP feature?

4. Does it increase development time or operational cost significantly?

5. Can it be tested after the MVP?

When a feature is valuable but not necessary for validation, it should be added to the post-MVP backlog rather than the MVP.

---

# Success Definition

The HanGo MVP succeeds when real learners can complete a structured scenario-based learning journey, use Chinese actively, receive useful AI support, and understand their progress well enough to continue studying.

The MVP does not succeed because it contains many features.

It succeeds because the complete core learning experience works and creates measurable value.
